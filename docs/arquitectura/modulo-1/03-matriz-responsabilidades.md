## Hallazgos de la línea base

- No se encontró una capa `Service` separada para reservas: `_build_reservation()` cumple ese rol dentro del router.
- No se encontró repositorio separado: `get_db()` es el adaptador y las consultas están en el router.
- Las reglas de disponibilidad/precio están repartidas entre router, `pricing_service.py` y `festivos.py`.
- La UI hace una previsualización de conflictos; la decisión persistente ocurre en backend.
- No se propone refactorización en esta entrega; los hallazgos quedan registrados para la Parte II.
